# MicroWIN SMART故障模式与验收清单

## 内容导航

- 参数丢失或大量数值变成0：看“工程构成与下载覆盖”。
- 数据块导入按钮为灰色：看“数据块导入入口”。
- 中文乱码：看“AWL文本格式”。
- LAD显示“无效程序段”：看“AWL/STL转梯形图”。
- 新增默认值或保持参数：看“参数恢复与保持区”。
- 准备交付：执行“分层验收清单”。
- 换表后大量未定义、粘贴追加：看“符号迁移与编辑错误”，并读 `symbol-migration.md`、`native-integration.md`。

## 符号迁移与编辑错误

| 现象 | 先核对的依据 | 不允许的捷径 |
|---|---|---|
| 错误33 | 全局符号或局部变量未定义；核对当前引用和所属表 | 随意给旧名称补地址或改算法消红叉 |
| DB错误2779 | 数据块使用未定义全局符号；核对显式地址和初值类型 | 把 REAL 的旧值直接解释成 DINT 或清空全部参数 |
| 错误32 | 指令操作数语法非法；检查是否发生文本追加 | 将输入动作完成当作替换成功 |
| 符号表矩形粘贴失败 | 载荷三列、CRLF、无尾空行及选择区域；本机 profile 先小样验证 | 把某次成功组合说成所有版本唯一根因 |
| 清表后出现大量错误 | 比较删表前后符号映射和程序/DB引用 | 把错误数量当错误码，或假定新表同址自动恢复旧名 |

错误定义来自 Siemens 主题32263357835；右键未定义符号选择现有符号见31937031051。“应用符号”有官方更新机制，但不保证清空旧定义后可恢复丢失映射。只改变符号显示模式不证明引用修复。每项修复要核对可执行地址/类型/顺序，重新全部编译与原生导出。

编辑失败后先记录当前文件、块、段、错误码、错误数量、最后动作和预期结果。查本版官方说明；同机制两次失败停止该方法，不循环切换视图、重复贴同段或猜按钮。界面状态受用户操作干扰时先重新观察，不沿用旧坐标。

## 工程构成与下载覆盖

MicroWIN SMART中的内容至少应分开理解：

- 程序块：OB、SBR和INT等执行逻辑。
- 数据块：V区参数下载初值。
- 系统块：CPU、通信、保持区等配置。
- 符号表和状态表：工程辅助信息，不等于现场实时值。
- PLC当前存储器：可能含调试后参数，不能由一份缺少数据块的导出文件重建。

只导出的程序AWL可能完全不含数据块。把这种工程导入后再在下载窗口勾选“数据块”或“全部”，会把目标工程中的空数据块或错误初值写入PLC，使原有V区设定丢失、归零或恢复到错误值。单纯在电脑中导入文件不会改变PLC；真正产生现场影响的是后续下载、清存储器或其他写入。

恢复前应分别备份：原始`.smart`、当前PLC程序块、数据块、系统块、HMI参数截图或导出，以及关键在线值。不要把“程序编译通过”当作“数据值已恢复”。

## 数据块导入入口

MicroWIN的导入命令会随项目树当前选择变化。数据块导入为灰色时，先单击项目树中的“数据块”节点，再打开导入命令。程序块AWL和数据块AWL必须从对应节点分别导入，不能用程序块导入替代数据块导入。

导入数据块前先确认它会替换什么，并保留目标工程现有数据块备份。导入后核对条目数、字节数、关键值和地址对齐，再考虑任何下载动作。

## AWL文本格式

老版本或中文环境的MicroWIN SMART常要求AWL使用CP936/GBK编码。可靠基线是：

- CP936/GBK；
- CRLF换行；
- 无UTF-8 BOM；
- 所有中文都能按CP936往返编码；
- 程序块和数据块使用各自正确的AWL包装标记。

不要仅凭编辑器里“看起来正常”判断编码。写出后重新按CP936读取并比较，检查换行和BOM。乱码修复不应改变任何可执行指令。

## AWL/STL转梯形图

### 关键限制

MicroWIN SMART的单个LAD程序段在水平方向和垂直方向最多延伸32个网格单元。这个限制不是“最多32条支路”：MOVR、MOVW、TON、比较框及复杂逻辑组合可能各占多个垂直或水平单元。

因此：

- 40条并联支路明显可能超限；
- 20条或更少仍可能超限；
- LPS/LRD/LPP堆栈成对且语法正确，也不保证MicroWIN能绘制成LAD；
- AWL编译0错误不等于每个Network都能在LAD中显示；
- 前面修改的Network正常，不代表后面原样导入的复杂Network正常。

### 推荐诊断顺序

1. 在隔离工程导入，不连接PLC。
2. 先检查导入日志和完整编译结果。
3. 逐段打开所有修改过的Network。
4. 继续向后浏览同一POU，记录每个出现“无效程序段”的Network编号。
5. 对照AWL检查：功能框数量、并联层数、嵌套逻辑栈、多个输出、定时器和边沿指令组合。
6. 先把一个代表性问题段改为有官方或原生范例依据的合法结构，实际导入验证；不规定固定的安全支路数，不只用静态支路计数预测成功。

### 可选结构改法

按对原编号和可读性的影响从小到大选择：

1. 在原Network内简化合法并联结构，前提是MicroWIN实测能显示且执行顺序不变。
2. 把复杂逻辑拆为多个小Network；最直观，但后续Network编号可能变化。
3. 把原Network逻辑移入辅助SBR，在原位置只保留CALL；可以保留主控制程序编号，但会增加程序块。
4. 用多个辅助SBR分别承载原控制段；编号最稳定，但结构更分散，应有清晰中文命名和索引。

不要用新增中间M位规避转换，除非已检查地址冲突、保持属性、首次扫描状态和对输出时序的影响。不要把原本同一扫描顺序的逻辑移到不同调用位置。

### 重复失败停止条件

同一种结构调整连续两次仍出现“无效程序段”时，应停止继续猜测支路上限。收集具体无效Network编号、截图、AWL正文和编译结果，重新选择拆分或辅助SBR方案。避免在未经MicroWIN实测的情况下批量改写后续所有程序段。

## 参数恢复与保持区

参数恢复逻辑应防止有效的HMI设定被PLC每扫描覆盖：

- 必须为正的参数可在不大于0时恢复默认值。
- 允许为负的温度等参数不能使用“不大于0”作为无效判断；通常只在等于0时恢复，或使用明确的有效范围。
- 派生时间或计算值应在基础值恢复之后计算。
- 没有可靠依据的参数不要猜值；标为未确认或保持停用。
- 停用设备的控制/报警逻辑与储罐监测、放空等相关逻辑要分开处理。

数据块初值和掉电保持是两件事。数据块决定下载初值；保持区决定断电或STOP/RUN后哪些V区内容保留。配置保持区时只覆盖明确的参数范围，不能把实时模拟量结果一起保持。

## 分层验收清单

### 文件与静态检查

- 原始`.smart`哈希保持不变，并有独立候选和回滚副本。
- AWL为GBK/CP936、CRLF、无BOM，中文往返无损。
- 程序块、Network数量和新增辅助SBR与批准方案一致。
- 比较符、地址、常数、线圈类型、定时器预设和执行顺序逐项一致。
- 未授权范围的可执行行保持一致。
- 数据块条目数、重复地址、地址重叠、VD/VW对齐和字节数均已检查。

### MicroWIN离线检查

- 程序块和数据块从正确节点分别导入。
- 所有修改Network均能显示为LAD，没有红色“无效程序段”。
- 同一POU剩余Network也已逐段浏览，不因只检查首段而漏掉后续无效段。
- “全部编译”显示0错误、0警告。
- 数据块字节数和关键初值与基线一致。
- 保存、关闭、重开工程后再次浏览并全部编译，结果一致。

### 现场前置条件

- 已备份PLC当前程序、数据和系统块，并有可执行回滚步骤。
- 参数经过工艺或设备负责人复核。
- 急停、故障、泄漏、阀位、压力、温度及其他安全联锁没有被旁路。
- 下载选项逐项确认，不使用“全部勾选”替代影响分析。
- 获得现场授权后才允许下载；下载后按批准的停机、启动、报警和联锁测试表验收。

## 结论措辞

报告时使用清晰的证据等级：

- “静态检查通过”：只证明文件结构和比对结果。
- “导入成功”：只证明MicroWIN接受文件。
- “LAD显示通过”：必须说明实际检查的Network范围。
- “编译通过”：必须有完整编译的错误和警告计数。
- “现场验收通过”：必须来自授权下载后的真实I/O和工艺测试。

不要把其中任何一级写成更高一级。
