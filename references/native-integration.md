# 原生集成与证据门槛

适用：Siemens MicroWIN SMART 的程序/符号/数据集成、MAIN 编辑与离线交付。没有现场写权限。这里的门槛是本用户工程约定；具体编辑行为有下列官方依据。

## 在点按钮之前确认什么

1. 当前窗口的绝对工程路径、CPU、软件版本、磁盘文件哈希与未保存状态。窗口标题相同不代表同一份工程。
2. 本次动作对象究竟是字符选区、操作数单元格、程序段集合、POU、用户表还是 DB 页；它们的全选和粘贴行为不同。
3. 库实现来自保全的原 SMART；受保护库的导出声明桩不能重建实现。记录库 POU、签名、V 区分配及版本。
4. 更改符号或 DB 前读 `symbol-migration.md`，准备引用处置和原值保全；先完成载荷预检。

只使用本环境允许的原生 UI/API 工具。一个会改变焦点/布局的动作完成后重新观察，再选下一个目标。无稳定焦点时不输入。不能为了保持流程进度猜测输入是否生效。

## 官方行为与操作选择

| 对象 | 已核实规则 | 操作约束 |
|---|---|---|
| POU 导入 | 含 OB1 删除现有全部 POU；只含 SBR/INT 替换相应编号，保留未列块 | 有受保护库时默认局部导入；完整重建须先证明库/数据/系统可重建且范围获批 |
| DB 导入 | 替换整个现有 DB | 使用已合并并核定类型/初值的完整 DB，不用增量覆盖 |
| 程序段粘贴 | 插在光标当前位置上方的行/梯级 | `Ctrl+A` 后粘贴不能未经验证就视为替换整个 MAIN |
| STL 覆盖 | INS/OVR 只切换字符插入/覆盖，不能像 LAD/FBD 用一条指令覆盖另一条 | 原位改一行时观察文本选区，使用 Home、Shift+End 选中目标行再替换并核对；不在旧文字末尾直接追加 |
| 未定义符号 | 可定义符号或选择现有符号 | 先核对目标地址/类型，再按官方菜单重绑；不为消错误任意造别名 |
| 符号显示 | Ctrl+Y 切换显示；应用符号另有命令 | 显示改变不作为重新绑定证据 |
| 导入编译错误 | 失败指令可能被加 `//`；LAD/FBD 不显示这些行注释 | 回到 STL 检查，并与原生导出逐指令核对，不能只看无红叉 |

小范围 MAIN 修复优先原位修改已定位行并核对该段全部指令。较大 MAIN 更新可用核实未占用的临时 SBR 承载，局部导入后以原生程序段对象转移；选择/替换方法必须在独立候选验证，不把文本粘贴当对象覆盖。清除旧正文或临时块仍遵守动作确认和回退规则。

### 已实测的 STL 整段正文替换

在 MicroWIN SMART V2.8.2 的独立候选工程中，MAIN 正文可以直接改 STL，无须改动通讯库，也无须借用临时 SBR。先保全原工程及原生导出，核实目标块和焦点，再采用以下已验证方法；换版本仍需单点验证：

1. 在目标 POU 的 STL 正文中用 Ctrl+Home、Ctrl+Shift+End 选到全文，观察选区覆盖首段至末段。不能只凭 Ctrl+A 判断全文已选。
2. 获准替换正文后删除选区，观察剩下的空白网络；点击其代码行，输入已预检的完整 NETWORK 正文。不输入 POU 包装头、END_BLOCK、MEND 或 RET。
3. 本机粘贴会在原空网络后生成新网络。核对首段确为空且焦点在该段后，删除这个多余空段；不能无条件删除第一段。随后验证网络数、首尾指令和全部调用。
4. 仅导入中文改名后的 SBR，旧 MAIN 可能仍引用旧 POU 名或旧符号，产生错误39/33。定位错误行并按地址和 POU 编号迁移引用，不要改库、加假别名或改算法来消错。
5. 全编译、保存重开、再次全编译，再导出逐指令和逐段注释比较。厂家受保护库的空导出桩不作为库实现等价证据。

该方法是已验证的编辑途径，不是自动认可逻辑或现场安全。遇到选区、段数或引用异常仍执行上文停止规则。

原生窗口的 UIA 文本可能先于同次截图刷新，导致截图已编译成功而文本仍是旧错误。重要结果另取一次新 UIA，核对准确工程路径、块列表及最终错误汇总，保留旧错误记录，不能选择性引用有利画面。

## 一次集成的停止条件

- 导入/粘贴出现非预期段数、红叉或字段追加：停止继续批量操作，保留错误和当前状态，查对应官方主题。
- 同一机制连续两次失败：停止该方法；返回确切源码/错误日志/合法范例分析，不用更多按钮组合代替原因诊断。
- `.err`、输出窗口中有未定义/语法/签名错误：不能进入“最终保存交付”；可保存明确标注未验收的工作副本。
- 库丢失、地址/类型变化、未授权 CPU 改型或逻辑变化：停止集成，回到保全副本与批准范围；不得靠删保护逻辑挤容量。

## 证据台账与失效规则

每一轮分配唯一目录，保留失败历史，不覆盖上轮报告。台账最少包含：

- 来源 `.smart`、生成器/输入清单、AWL、符号、DB、系统配置/库证据的 SHA-256。
- 软件/CPU/库身份；目标 POU 与 Network 清单；编译程序字节/容量、数据字节、程序/数据/系统各自错误警告。
- 原生 `.smart`、原生导出、LAD PDF、编译日志的哈希；每条证据对应的输入哈希与实际检查范围。
- 当前失败、未核实项、离线/现场层级；受保护库内部不可见不能算已逐段审查。

| 修改 | 必须重新核验的下游证据 |
|---|---|
| 源/地址/类型/符号或导入载荷 | 静态检查、原生往返、全部编译、受影响 LAD 与保存重开 |
| DB/保持配置/系统块 | 参数与首扫/保持契约、全部编译、保存重开；影响逻辑时重跑相应测试 |
| CPU/库/软件版本 | 容量/签名/地址布局、全部编译、LAD、往返、保存重开 |
| 仅报告说明文字 | 对应说明复核；不能顺便改变结果或冒用旧哈希 |

自动脚本只能核对文件和声明依赖。对未导出的原生系统配置及未保存编辑状态，必须用原生证据人工核对；缺证据是“待验”。

## 交付顺序

1. 源/编码/范围检查通过；新旧引用、初值、保持与库内存都已核对。
2. 原生全部编译：程序、数据、系统均零错误、零警告；超容量时不靠删保护通过。
3. 所有受影响 LAD 段和同 POU 剩余段核查；全量打印须检查 POU/段号覆盖、无效段文本和实际图形。只抽查时如实报告范围，不声称全量目视完成。
4. 保存、关闭、重开磁盘工程，再全部编译；有窗口状态差异则增加全新进程验证。重开后再导出作为最终比对输入。
5. 对照原生往返的指令、操作数、常量、顺序、数据块值；文本差异与有证据的等价解释分开记录。零差异报告不应通过广泛忽略规则制造。
6. 以精确文件路径和哈希交付，并标明现场未执行事项。字段接收成功、通讯应答、设备动作完成、实际工艺效果是不同证据。

静态模型、原生编译和现场验收不能相互替代。通过以上步骤才可称对应文件“离线验收通过”，不保证任意新程序一次成功。
