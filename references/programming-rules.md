# PLC 编写前与编写中的约束

这些规则用于决定代码如何生成。最终验收仍要做，但不能把发现基本限制的责任推到验收阶段。

证据标记：**官方** = 本次实际查阅的 Siemens 帮助；**工程约定** = 为本用户制定的实现选择；**实测** = 本机离线行为。Siemens 规则只适用于匹配的 MicroWIN SMART 软件与库版本。

## 开始写第一条指令之前

先从现有工程、设备说明和本次需求建立一份简短的编写约束表。已有资料能确认的项目自行查明，不要求用户重复回答。

| 要先决定的内容 | 代码生成时必须遵守的约束 |
|---|---|
| CPU、软件、固件和库版本；基线工程 | 不混用其他 PLC 的指令、库签名、容量或导入行为；保留原文件校验值 |
| 输出控制者、实际反馈和安全优先级 | 命令、反馈、通信成功、有效工艺输出分别命名；原联锁仍作最终裁决 |
| 数据地址、类型、字节范围、单位与写入者 | 先画占用表，再分配地址；包括位/字节/字/双字重叠、库区、HMI/云端和间接访问 |
| 首扫、运行、停机、断电再上电状态 | 决定哪些值初始化、保持、失效、需人工确认；不能每扫描覆盖有效设定 |
| 每个 POU 的调用位置和每扫描调用次数 | 定时器、边沿、结果覆盖和通信状态的先后顺序要先确定 |
| 每种 Network 的形态及 CALL 签名 | 选择下面允许的生成结构；陌生结构先查对应指令原文/原生范例，再批量生成 |
| 本次导入对象与回退入口 | 先决定局部 SBR 导入还是完整工程集成；避免写到最后才发现库会被删除 |
| 全部符号表、原生名称与显示标签；现存符号引用 | 符号首字符、编码/长度、跨表名称/地址必须核对；删除/更名前列出 MAIN、SBR/INT、DB 与辅助表引用及处置 |
| 容量与验证依据 | 查目标 CPU 官方容量；尽早用真实库和代表结构原生编译。文本文件大小、指令行数及主机模型不能作为装得下的证明 |

无法确认安全频率、联锁极性、设备量程或通信写入含义时，不编造数值或默认开启。可继续编写已明确的离线部分，把依赖未知值的功能停用并列明欠缺依据。此条是本项目工程约定，不是 Siemens 通用默认值。

## 1. 从 LAD 结构生成 AWL，而非任意拼接 STL

**官方**：[S01][S02][S03][S04]。

- Network 默认是一条完整独立逻辑。触点开头，线圈或功能框形成完整输出；多输出使用已知合法的并联结构。普通线圈终止对应逻辑路径，不在一条水平路径上串联多个线圈。
- 新增一条无关条件、独立计时或独立覆盖写入时，从生成阶段就开始一个新的 Network。不要先拼进同一段再期待自动转换器拆分。
- 一个段沿水平、垂直方向各最多 32 个网格单元。按功能框实际占格估算，不能以“指令少于 32 条”或“并联少于 32 路”代替。接近限制时提前拆段并保留扫描位置，不规定未经实测的统一支路上限。
- 同一条件下的多输出，串联带 ENO 的功能框和并联功能框行为不同：串联中前一框 ENO 关闭会影响后续；并联其他支路仍可执行。生成代码时先决定失败是否应阻断后续输出，再决定串/并联及 AENO，禁止为画图方便互换。
- `LD` 会压入逻辑栈，`ALD/OLD` 合并栈顶两层，`LPS/LRD/LPP` 维护分支。生成嵌套逻辑时维护栈结构；不能把所有重复 LD 机械拆段，也不能把任意有效 STL 都当成可转 LAD。
- 为复杂或首次使用的形态选取官方 LAD→STL 范例或本工程原生导出。没有依据就用更简单的已知合法结构。代表段的原生检查是编写过程中的小步确认，不能等全部写完才第一次打开 LAD。

## 2. 带布尔能流输入的 CALL 必须按规定展开

**官方**：[S05][S06] 明确给出两种写法，简写只能在 STL 显示。

```text
// 官方示例的结构，名称与实际参数须由目标 POU 签名决定
Network 1
LD EnableCondition
= L60.0
LD FirstCondition
= L63.7
LD L60.0
CALL TargetSBR, L63.7, ...
```

- 以上是说明结构的占位示例，不是可直接导入的程序。实际参数个数、顺序、数据类型和哪几个 BOOL 属于能流输入，均以实际库/POU 为准。
- 不能把它压缩成 `LD EnableCondition / CALL TargetSBR, FirstCondition,...` 并作为 LAD 交付。官方指出能流 BOOL 必须按编译器形式存入 L 区才能自由切换视图。
- **LB60～LB63 是 MicroWIN 保留给调用参数的 4 字节。不要把其中的位用作跨 Network 的自定义缓存、锁存、心跳或公共状态。** 保留区只在相应原生 CALL 连接结构中使用；需要跨段暂存时，先在变量表/内存清单中分配不冲突且生命周期合适的变量。
- CALL 的参数按 IN、IN_OUT、OUT 排序；TEMP 不作为实参传递。普通 BOOL 地址输入和 BOOL 能流输入不可混为一谈。
- 参数不自动转换数据类型。调用前显式完成所需转换；地址是 DWORD 指针值，OUT/IN_OUT 不能传常数。
- 子例程的 OUT 不能依赖上次调用值，必须为当前调用的各条返回路径赋值。调用期间才有效的数据可用 TEMP；要跨扫描保留的状态使用明确的状态区。
- 不假定库名总对应某个 SBR 编号。生成前核对本工程实际 POU、符号绑定、签名和现有调用；不通过盲目改编号消除红叉。

## 3. 先确定类型、存储范围和运算语义

**官方**：[S05][S07][S08]；内存分配表为工程约定。

- 地址宽度不等于数据类型：VD 可以存 REAL 或 DINT。变量表先写明类型和单位，再选 `MOVR`、`AR/LDR` 等对应实数指令，不能因为都是 4 字节就用整数 `AD/LDD` 比较。
- `B` 比较是无符号字节，`W` 比较是有符号整数，`D` 是有符号双整数，`R` 是实数。无符号寄存器大于 32767 时不能直接套有符号字比较；先选择正确的扩展与转换。
- 原始寄存器值、工程单位值、目标值、状态字和故障码应有明确类型；倍率、字节序、双寄存器字序以设备手册为准。
- 每个字节地址的占用范围必须清楚，例如 VW 占两字节、VD 占四字节；库分配区、位标志和宽类型都参加冲突检查。不要用“这个地址没出现在直接指令里”推断无人写入。
- 指针和 REAL 值先初始化；非法地址和 NaN 会使比较产生错误/假值。官方还指出比较指令会执行，即使前面的能流关闭；不能仅加前置触点就假定非法间接访问被安全屏蔽。
- 先规定量程、符号、溢出、分母为零和无效值处置，再生成换算和限幅。不能依赖编译器自动推断工艺单位或修正错误类型。

## 4. 扫描顺序、边沿和定时器是编写条件

**官方**：[S09][S10][S11][S12]。

- 主程序按指令顺序执行，CALL 返回后接着执行下一条。拆段不能交换先判断后清零、先消费请求后确认或多次覆盖结果的顺序。
- 普通 I/O 经过程映像处理；立即 I/O 和中断有不同时间行为。不能把写入 Q 的命令当成已经收到设备运行反馈，更不能当成泵已有效打液。
- 普通子例程共享累加器，默认不自动保存/恢复 AC。调用前后要保留的数据不应无依据地留在 AC 中。Siemens Modbus 主站库单独声明会保存/恢复 AC，不能把这个例外泛化给其他 SBR。
- EU/ED 在 CPU 首扫保存初始状态，**不会在首扫检测跳变**。不能设计“上电信号为真，就依靠 EU 一定发首个请求”；首扫启动应使用明确初始化/状态流程。
- 同一扫描多次调用同一 SBR 时，官方要求避免其中使用边沿、定时器、计数器。复用带状态函数前先决定实例状态与调用次数，不假定它像普通无状态函数。
- 定时器编号决定时间基准。先分配唯一用途、核算 PT，再生成程序；100 ms 定时器必须每扫描只执行一次，漏执行或重复执行都会影响计时。1 ms、10 ms 和 100 ms 定时器更新时刻不同，不可随意互换。

## 5. Modbus 从通信生命周期设计开始

**官方**：[S13]～[S18]。

- `MBUS_CTRL/MB_CTRL2` 必须包括首扫在内每扫描调用，不能只首扫调用。初始化成功后再调用 MSG；通信库依赖的中断不能被用户程序禁用。
- 每个同一主站库实例在任一时刻只能有一条 MSG 活动。先设计单一总线拥有者及请求队列，再写各从站读取条件。
- `First` 仅一个扫描脉冲；`EN` 必须持续到 `Done`。因此不能只用 First 脉冲作为整个功能框使能。`Done` 也可能表示错误终止，只有 Done 为真时 Error 才有效。
- 请求参数和发送缓冲在等待期间由该在途请求独占。取消上位请求不能凭空撤回已发送的帧；必须设计收尾和不确定结果。
- `Count` 是寄存器字数或位数，DataPtr 即使指向字也应使用 `&VB...`；接收缓冲按实际字节数预留。
- 先分清设备手册的零起始偏移、十六进制写法和 Siemens 一起始 Addr。保持寄存器采用有效的 5/6 位表示，不能对大偏移机械加 40001 得到无效区间。示意：偏移 0x3000 = 12288，对应 400001 + 12288 = 412289；这仅说明库换算，不代替设备地址依据。
- 库默认对若干错误额外重发两次。若本项目控制写要求“不自动重试”，必须在编写前决定库级重试策略；只关闭上位机重试不够。通过本工程库符号确定实际重试字段地址，不能复制别的工程地址。
- 单寄存器写是否使用 FC06 或强制 FC16，按实际从站支持和 `mModbusForceMulti` 配置设计。工程区、写权限、频率源、运行命令源、端子覆盖和掉电行为须和变频器手册一起核对。
- 本机帮助所述主站库需 286 字节 V 区；起点由工程分配，库版本变更应重查。串口被分配为 Modbus 后不能同时用于其他协议。
- 原始读值、有效/陈旧质量和时间要一起设计；协议成功只证明通信完成。把它当作设备执行或泵流量证明属于工程语义错误。

## 6. 初始化、保持和导入在写之前决定

**官方**：[S19][S20]。

- 上电顺序是清零 V/M/C/T，复制数据块初值，再恢复配置的保持值。数据块初值、保持配置和当前现场值是三个概念，生成初始化逻辑前分别核对。
- 工艺配置与瞬时命令/状态分开决定保持；不要把整个连续大段一律保持，也不要在每扫描重写有效人工设定。
- 工程首扫关闭通信或配置缺省为零时，必须同时考虑设备是否仍保留远程频率源，避免 PLC 和 VFD 模式失配。此项应在设计里解决或保持功能未投入，不能等待现场首次上电才发现。
- 含 OB1 的 ASCII 导入会删除全部现有 POU，再按文件重建。只含 SBR/INT 的导入只替换对应编号。生成文件前就选择集成方式，受保护库仅有导出桩时不能整体重建。
- 导入数据块会删除并替换现有数据块。需要新增默认值时先合并原参数，不能生成只有增量的 DB 去覆盖整个工程。
- 官方说明导入时编译失败的指令可能被改为 `//` 注释，且 LAD/FBD 不显示这些行注释。因此源文件包装、编码和库签名必须先正确；导入后还必须核对可执行语句未被静默注释掉。

## 7. 符号和原生载荷属于生成接口

涉及生成、导入、符号表或 DB 变更时，继续读 [symbol-migration.md](symbol-migration.md) 和 [preflight-tool.md](preflight-tool.md)。

- 先确定“显示标签、合法原生符号、绝对地址、类型、单位、表归属”的对应关系。原生名称的规范化不能改变地址和数据类型；名称冲突不能靠随意加地址解决。
- 符号表、程序正文与 DB 是分开的引用者。新表中出现同一地址，不证明旧名称引用已重新绑定。变更前查引用，变更后检查原生符号应用与全部编译结果。
- 程序 AWL 文件的 GBK/CRLF profile 和 Unicode 表格剪贴板的三列/行尾 profile 分开验证；后者不能照搬 AWL 文件编码规则。
- 可复现生成是工程要求：源未变时二次生成应一致。允许生成时间等非执行元数据差异时，明确列出；不可把不稳定的地址、类型或指令顺序当元数据忽略。

## 8. 用检查门槛落实规则

预检脚本只验证声明输入和支持的子集。缺全表清单、间接访问范围、实际库签名或目标固件证据时，明确未覆盖项；不得用脚本无错误代替它们。位与字的有意视图可经显式别名/范围依据核对，不禁止所有内存重叠。

每个原生阶段的输入、输出及证据保存 SHA-256。程序、符号、DB、系统块、库或 CPU 变化后，重做受影响的编译、LAD、往返和保存重开检查。仅有旧的成功日志时，当前阶段是“待验”，不是“通过”。具体操作见 [native-integration.md](native-integration.md)。
