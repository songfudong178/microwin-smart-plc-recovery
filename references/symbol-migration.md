# MicroWIN SMART 符号迁移与传输契约

本参考适用于符号重命名、清表重建、地址重绑、数据块符号恢复，以及符号生成器修改。**符号整理是引用迁移，不只是表格美化。** 不因此改变控制逻辑、调用顺序、初值、保持区或现场设备状态；不授权 PLC 下载、在线写值或强制。

证据标记：**官方**为下表 Siemens 帮助明确记载；**工程约定**为本技能的防错与验收要求；**本机实测**仅约束记录过的应用版本、区域设置和编辑器组合，不外推成所有版本的规则。

## 1. 先建立受控符号清单

每个变量至少保留以下字段，再生成符号表或修改原生工程：

| 字段 | 要求 |
|---|---|
| 稳定变量标识 | 独立于显示名称和地址，能关联变更前后同一变量。 |
| 原生符号／显示标签 | 分开存储；面向人的显示标签不一定是合法 PLC 标识符。 |
| 地址与范围 | 存储区、绝对地址、字节／位区间；不能只比较地址字符串。 |
| 语义类型 | BOOL、整数、实数等，并记录单位、缩放与有效范围；宽度相同不代表类型相同。 |
| 所属表与作用域 | 用户、I/O、系统、库或 POU 局部变量；区分全局与局部。 |
| 引用与写入者 | 程序、数据块、状态表以及本次范围内的外部消费者；记录读写关系。 |
| 迁移映射 | 旧名 → 已验证地址及类型 → 新名；记录被批准的别名或重叠。 |

- **官方（31986000267）**：全局符号作用于全部 POU。拆成多个表不能使重复的全局名称合法。局部变量归属于各自 POU。
- **官方（31986000267）**：名称不能以数字开头，不得使用保留关键字；支持字母数字、下划线及扩展字符。帮助给出的名称上限为 **23 个单字节字符**，注释上限为 **79 个字符**。
- **工程约定**：检查目标软件、代码页和实际原生行为。中文字符数不能直接等同于该单字节限制；编码字节数可以作为保守的预检查，但不能代替原生验证或宣称所有版本都采用同一 Unicode 长度算法。
- **工程约定**：名称和地址检查必须覆盖所有相关表，不能只检查新用户表。已有 I/O、系统或库表拥有的符号，不应另建一个同址用户符号来绕过名称问题。合法的位／字访问重叠必须有明确用途、类型和写入者约定，不能一概判错或无条件放行。
- **官方（31986000267）**：红字表示语法无效，红色下划线可表示重复名称、重复地址等无效使用，绿色下划线表示缺少地址的未定义符号。编辑后用 Tab、Enter 或方向键提交单元格，再观察状态。

## 2. 删除或批量改名前，必须闭合全部引用

按以下次序进行，不采用“先删旧表，再看编译器缺什么”的方式：

1. 保留可回退的原生工程副本；记录软件版本、CPU 身份、来源和哈希。
2. 盘点所有符号表、POU 及数据块标签页，生成旧名／地址／类型／归属清单；保留本次范围内状态表等辅助引用证据。
3. 编译基线；条件允许时执行原生 **MAIN 全程序导出**和**完整数据块导出**。基线不能编译或导出时，明确记录缺口，保留原生工程、打印或剪贴板证据，不声称已有完整导出基线。
4. 为每个待删或待改名称确定全部引用位置和替换方式，包括 MAIN、SBR、INT 与数据块中的初始化表达式。
5. 地址、语义类型、表归属或引用替换尚不明确时，停止删除／批量重命名。不能通过临时猜地址或增加旧名别名来消除报错。

**工程约定**：默认保留库、POU、系统和 I/O 表；确有迁移需求时必须单独说明目标与影响。官方针对旧 `.mwp` 转换时系统符号处理的说明，不是任意删除当前系统表的依据。

**官方（32196111755、32196112523）**：导入含 OB1 的源文件会删除并重建所有 POU；仅 SBR／INT 的源文件按编号替换对应块并保留 MAIN 和未包含块。数据块导入会替换整个现有数据块并据文件重建标签页。因此，修复符号不能顺手导入缺少受保护库的完整 OB1 文件，也不能把局部数据修复当成无影响的整块导入。

## 3. 先在原生一次性副本验证迁移行为

**工程约定**：批量操作前，使用可丢弃副本验证一个有代表性的符号，并使它同时被程序和数据块引用；若任务涉及中文、跨表、已有 I/O 名称等情形，也应覆盖这些情形。

验证过程必须包含：原始引用记录 → 修改名称或绑定 → 应用符号／选择符号 → 编译 → 保存 → 关闭重开 → 再次检查引用和类型。

不要假定在编辑器输入绝对地址后，工程内部一定永久保留“纯地址、无符号绑定”。符号显示及编辑器可能解析成已有名称，需以该版本实测和导出结果确认。

### 支持的操作与边界

- **Apply Symbols to Project／将符号应用于项目（官方 31992317835）**：用于让项目使用新增、原有和修改后的名称；不是“删除旧名称后能自动重建所有地址绑定”的保证。数字常量也不会自动变成符号常量。
- **Select Symbol／选择符号（官方 31987318667）**：程序编辑器可选择现有符号来替换先前的符号赋值，状态表和数据块也支持选取符号；帮助明确按相应数据大小及是否支持常量筛选。出现在列表中不证明 REAL/DINT 等语义类型正确，仍须按已验证映射逐项重绑，不用于猜测缺失变量。
- **绝对／符号显示（官方 31904017803）**：Ctrl+Y 切换寻址显示，Ctrl+T 显示 LAD／FBD 的符号信息表；视图还可选择绝对、符号或两者。显示切换不等于修复未定义绑定。

引用已经损坏时，优先依据保留的清单恢复原绑定或进行可验证的重绑。确需源文件恢复时，仅使用同一受控来源、限定范围的 SBR／INT 导入和经验证的 MAIN 内容替换，并遵守主技能的导入、库保护和 LAD 验收要求；不能靠另一个近似版本“补齐”。

## 4. 数据块必须先验证类型，再改成显式地址

- **官方（31984308363）**：数据块初始化地址属于 V／VB／VW／VD；首次赋值必须有显式地址或已定义符号，后续允许隐式地址。分隔符可以为空格、Tab 或逗号，注释为 `//`；Enter 会触发原生行格式化。
- **工程约定**：符号迁移时优先采用经过映射验证的显式地址，避免未定义名称及隐式地址连带偏移。但必须先确认语义类型、占用范围、数值表示和原初值，不能因地址是双字就将 REAL 当成 DINT，或反之。
- **官方（31984433803）**：编译可发现数据块地址重复／重叠、地址区错误、宽度不足、数值／顺序／语法错误。
- **工程约定**：保留未涉及的全部数据、标签页与保持配置。离线数据块修复不授权向运行中的 PLC 下载初始化数据。

## 5. 生成器与传输载荷分开验证

### 5.1 单一元数据，可重复生成

**工程约定**：程序、符号和初始化数据应从同一受控清单取得名称、地址、语义类型、表归属及初值。必须检查：

1. 原生名称合法、编码可表示、长度符合已验证配置；显示标签不直接充当标识符。
2. 新旧表合并后的名称冲突、地址区间重叠及类型冲突。
3. 同一输入重复生成得到相同输出；生成物具有来源、版本和哈希清单。
4. 修复作用于生成源或生成器，而不只手改一次粘贴文件；重新生成后仍然正确。

内容或哈希变化后，受影响的导入、编译、导出、LAD 与保存重开证据失效，必须重新验证。

### 5.2 AWL／ASCII 文件与 Unicode TSV 剪贴板不是同一契约

| 载荷 | 验证内容 |
|---|---|
| AWL／ASCII 导入文件 | 通过原生导出确认包装语法；按目标版本验证代码页、换行、BOM、编码往返及 `.err` 结果。不能仅按扩展名推断格式。 |
| 符号表 TSV 剪贴板 | 与目标表匹配的名称、地址、注释三列；无表头；字段内 Tab／换行须按明确规则拒绝或规范化；核对行列数。Unicode 剪贴板的文本与文件字节编码分别验证。 |

**官方（31938303883）**支持符号表信息列与 Excel 互相复制，也支持数据块与文本编辑器互相复制；这不保证任意 CSV 能直接导入，也不规定所有剪贴板环境采用同一种换行或编码。

**本机实测**：曾有特定软件／区域设置／编辑器组合在使用 **CRLF 且没有末尾换行或额外空行**的 TSV 后恢复矩形粘贴。此组合记录为本地传输配置，不把其中任一项独立认定为所有版本的根因或 Siemens 通用规定。应记录应用版本、区域／代码页、复制程序和粘贴目标，先少量行验证。不能因为 AWL 使用 CP936／GBK，就把 Unicode TSV 剪贴板也规定成“必须 GBK”。

## 6. 迁移验收：比较实际操作数，不只看编译通过

按次序保留证据：

1. **原生编译**：程序、数据块与系统配置结果分别记录；默认工程验收为零错误、零警告，不把错误消失等同于验收完成。已有警告若不在本次授权范围内，单列并报告验收未闭合，不擅自改逻辑消除。符号表无红线不能代替完整编译。
2. **原生程序及完整数据块导出**：检查文件非空且确为本次工程产生；将新旧名称通过已验证映射归一为绝对地址与语义类型，再比较指令、操作数、常量、调用顺序、POU／库身份，以及数据块地址范围、带类型的初值和对应字节语义。
3. **导入失真检查**：检查 STL 和导出文件，确认没有应执行指令因失败变成 `//` 注释。官方说明 ASCII 导入编译失败的语句可能被注释，且在 LAD／FBD 中不可见（32196111755）。
4. **生命周期不变**：确认首次扫描、保持／非保持归属、初始化顺序和原有控制逻辑未因迁移改变。
5. **原生 LAD 检查**：按主技能验收范围检查可编辑网络；受保护库内部不伪装成已展开验收。静态检查、全编译、LAD 覆盖、保存重开和现场验收是不同结论。
6. **保存重开复验**：保存后在明确身份的原生工程中重开，再检查编译、符号及数据块。缺少导出或无法建立可靠映射时，写明证据缺口，不声称前后逻辑完全等价。

### 错误代码与错误总数

**官方（32263357835）**：

| 错误代码 | 原文含义 |
|---|---|
| 33 | 指令操作数的全局符号或局部变量未定义。 |
| 2779 | 未定义的全局符号。 |

错误列表应记录“代码、对象范围、位置、符号及原因”；界面显示的**错误总数**不是错误代码。例如一次本机事件显示的“119 个错误”是程序和数据块检查的合计，不应写成“错误码 119”。大量同名引用错误通常应先检查符号绑定及迁移闭包，不能据数量推断控制算法本身失效。
